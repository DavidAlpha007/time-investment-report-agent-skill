# 红线与置信度规范

违反以下任一条，报告即失去价值。这不是风格建议，是准入条件。

---

## 一、四条红线

### 红线 1 · 绝不给「值不值得」打分

**禁止出现**：

- 「综合来看值得一看」
- 「推荐指数 4 星」
- 「不建议购买」
- 任何形式的总结性评分

**替换为**：

- 「第 68 集起单集评分跌破 6.0，且此后再未回到 7.0 以上」
- 「视频部分只占总投入的 24.5%，其余 75% 是实验与作业」
- 「该课程大纲不含 transformer、LLM、MLOps 与部署」

理由：用户会反驳一个评分，但不会反驳一条可核验的事实。

### 红线 2 · 永远保留第三个「放弃」选项

**C 选项必须包含**：

1. 精确到小时数的「省下多少」
2. **具体的替代动作**（不是「不看了」就完事）

示例：

> **选项 C · 放弃**
> 省下 70.2 小时。改用：只看 S1–S6，在 S6E10 停止（投入 52 小时），
> 或改看原著前 3 部改编的其他系列。若目的是「了解叙事结构」而非「看完结局」，
> 可直接读 A Song of Ice and Fire 的结构分析长文（约 40 分钟）。

**一份每次都推荐「看」的报告就是软文。**

### 红线 3 · 每一格都标置信度

一次被抓到编数据，信任归零且不可恢复。

### 红线 4 · 只做 ≥ 10 小时的内容

短视频、单篇文章不做。净收益模型显示那里的收益约等于零甚至为负。

## 二、置信度四级标注规范

| 标记 | 含义 | 使用要求 |
|---|---|---|
| `[官方]` | 来自出品方 / 平台官方页面 | 可附链接 |
| `[聚合]` | 来自公开评价聚合 | **必须注明样本规模**与聚合口径 |
| `[推算]` | 由上述数据计算得出 | **必须给出算式**或注明用脚本计算 |
| `[未验证]` | 未取得证据 | **必须明确写出「未验证」**，不得含糊带过 |

### 常见错误

| 错误做法 | 正确做法 |
|---|---|
| 用「约」「大概」掩盖没查到 | 标 `[未验证]`，或整格留空 |
| 把推算值写得像官方数据 | 标 `[推算]` 并附算式 |
| 只写「评分 8.8」不写来源 | 标 `[聚合]` + 评价人数 |
| 搜不到就自己估一个合理值 | 禁止。这是数据幻觉，红线级错误 |

## 三、诚实声明模板

每份报告末尾必须附。方括号内如实填写，不得美化。

```
## 诚实声明

本报告由 [人工 / AI 辅助] 基于公开可核验的元数据与公开评价聚合生成。

报告作者对内容的实际接触程度：
[ ] 已完成全部内容
[ ] 部分完成（说明到哪个位置：____）
[ ] 未实际消费任何内容，仅基于公开数据

所有推算值已在各格标注 [推算] 并附算式；
未取得证据的项目已标注 [未验证]，未做任何补全性猜测。

报告生成日期：____
```

**示例（三份样例报告的声明）**：

> 这三份报告由 AI 基于公开可核验的元数据与公开评价聚合生成，
> **报告作者并未观看全部 73 集、并未完成该课程、并未逐页阅读该书**。
> 所有推算值已在每份报告的「数据来源与置信度」中明确标注。

## 四、交付后的强制动作

48 小时后追问一句，不能跳过：

> 「这份报告里，哪几个格子对你做决定真的有用？」

同时记录用户实际选择了 A / B / C 哪一项。

**这两个数据是该方法唯一真正的核心资产**——比任何评分、任何模板都重要。
它回答的是「这份报告到底有没有价值」，而不是「用户喜不喜欢它」。

---

## 五、自查清单（成稿后逐条勾）

- [ ] 全篇没有任何「值不值得」的总结性判断或评分
- [ ] 三个选项齐全，且 C 选项有具体替代动作和省下的小时数
- [ ] 每一格都有置信度标记，无一处裸数据
- [ ] 所有 `[推算]` 都附了算式或注明脚本计算
- [ ] 所有 `[未验证]` 都明确写出，没有含糊带过
- [ ] 使用了时长加权均分，而非算术均分（差值 ≥ 0.3 时脚本会报警）
- [ ] 叙事型内容的尾部已单独提示（峰终效应）
- [ ] 已附诚实声明，并如实填写接触程度
- [ ] 对象总时长 ≥ 10 小时（否则应直接拒绝出报告）
