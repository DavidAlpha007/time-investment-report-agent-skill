# 时间投资评估报告 · Time Investment Report

> 把「要不要投入时间」从一个感觉问题，变成一笔可核验的账。

一门课 95 小时、一部长剧 70 小时、一本书 576 页——这些**高度不可逆**的时间投入，
大多数人靠「豆瓣评分 8.8」或朋友一句话就做了决定。

但 8.8 分既没告诉你前 7 季是稳定高质量，也没告诉你终季会跌到 6.4。
**平均分把最重要的信息压平了。**

这个 skill 提供一套七格方法，在下单 / 开追 / 开读之前，先把时间的**结构账**算清楚。

---

## 它做什么，不做什么

| ✅ 做 | ❌ 不做 |
|---|---|
| 算清总时长与按你节奏的完成日期 | 不打分、不评级、不写「推荐 / 不推荐」 |
| 按时间轴拆开结构，标出各段占比 | 不替你做决定 |
| 定位密度异常点：铺垫段、崩塌点、注水段 | 不给「值不值得」的总结性判断 |
| 判定时效折损（更新距今多久、缺了什么） | 不为了凑满七格而编数据 |
| 找更短的替代来源（尤其作者本人的压缩版） | — |
| 给出三个选项：全量 / 取核心段 / **放弃** | 绝不省略「放弃」选项 |

**核心理念**：用户会反驳一个评分，但不会反驳一条可核验的事实。
所以这里输出的永远是「第 68 集起评分跌破 6.0」，而不是「这部剧不值得看」。

---

## 三条铁律

1. **绝不给「值不值得」打分。** 品味无法被代理。
2. **永远保留第三个「放弃」选项。** 一份每次都推荐「看」的报告就是软文。
3. **每一格都标置信度。** 一次被抓到编数据，信任归零且不可恢复。

## 快速开始

### 安装（作为 Agent Skill）

复制到你的 skills 目录：

```bash
# WorkBuddy / CodeBuddy
cp -r time-investment-report ~/.workbuddy/skills/

# 或 Claude Code
cp -r time-investment-report ~/.claude/skills/
```

然后对 agent 说：

> 「我在犹豫要不要买 XX 课 / 追 XX 剧 / 读 XX 书，帮我做一份时间投资评估。」

### 安装（仅用脚本）

脚本是纯 Python 标准库，无依赖，可直接用：

```bash
python3 scripts/tir.py budget --hours 70.2 --per-week 6
python3 scripts/tir.py timeline --input segments.json
python3 scripts/tir.py scaffold --title "..." --type course
```

## 七格结构

| 格 | 名称 | 问什么 |
|---|---|---|
| 0 | 基础账 | 总篇幅、价格、评分规模、最近更新时间 |
| 1 | 时间账单 | 纯时长 ÷ 你的可用节奏 = 需要多少周 |
| 2 | 结构拆解 | 按章节 / 季 / 模块拆开，时间花在哪些格子里 |
| 3 | 密度异常点 | 铺垫段、崩塌点、注水段（看**分布**，不看平均分） |
| 4 | 时效折损 | 最近更新距今多久？你的目标是否依赖它没覆盖的内容？ |
| 5 | 更短替代源 | 有没有作者本人的压缩版、官方摘要、精华段？ |
| 6 | 三个选项 | 全量 / 取核心段 / **放弃** |

## 脚本

### `tir.py budget` —— 时间账单与净收益

```bash
python3 scripts/tir.py budget --hours 70.2 --per-week 6
```

输出所需周数、预计完成日，并判定这个对象**是否值得出报告**：

| 对象 | 净收益 |
|---|---|
| 1 分钟短视频 | **−9.6 分钟**（不如自己划走） |
| 70 小时长剧 | 1670 分钟（27.8 小时） |
| 200 小时网课 | 4790 分钟（79.8 小时） |

长短之间差约 **2000 倍**——这就是本方法只服务 ≥ 10 小时投入的原因。

### `tir.py timeline` —— 时间轴分布分析

输入分段数据：

```json
{
  "object": "权力的游戏",
  "good": 7.0,
  "bad": 6.0,
  "segments": [
    {"label": "S1", "minutes": 550, "rating": 9.1},
    {"label": "S2", "minutes": 560, "rating": 9.3}
  ]
}
```

输出：**时长加权均分**、好评区间时长占比、低分区间占比、
**崩点**（可复现定义：尾部加权均分低于全局 1.0 分且尾部占比 ≥ 5%）、
以及加权均分与算术均分的差值告警。

### `tir.py scaffold` —— 生成报告骨架

```bash
python3 scripts/tir.py scaffold --title "..." --type course
```

支持 `course` / `series` / `book` / `report` / `podcast` / `community`，
每种类型附带**专属的排查提示**（例如书籍必查「作者本人的更短原版」）。

## 为什么只做长内容

过滤器的价值 = 避免的损失。假设评估准确率 80%、阅读报告耗时 10 分钟：

- 一条 1 分钟短视频：期望节省 0.4 分钟，净收益 **−9.6 分钟**。而你自己划走只要 0.5 秒。
- 一门 200 小时网课：期望节省 4800 分钟，净收益 **79.8 小时**。

**在短视频场景，过滤器不是没用，是多余。**

而且刷 feed 的人不是在寻找价值，是在消磨时间——你帮他过滤掉内容，
他反而不知道该干什么。**在那个场景里，过滤器是反用户的。**

---

## 已知边界

- **只服务 ≥ 10 小时的投入。** 低于此线的请求应被拒绝。
- **不处理无公开数据的对象**（内部资料、未上映内容），此时降级为「决策清单」。
- **叙事型 vs 知识型，尾部处理方式不同**：剧集受峰终效应支配，尾部占比小也要单独提示；课程报告可按占比处理。
- **这不是评分工具的替代品**，而是它的补充：评分告诉你「大家觉得怎样」，这里告诉你「你的时间具体花在哪」。
